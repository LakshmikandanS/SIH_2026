# Block 08 — Observability / Metrics / Evaluation

## Role

Observability is not just a dashboard.

For this workbench it provides:
- operational monitoring
- agent traces
- model evaluation
- security evidence
- provenance
- zero-egress proof

## Three layers

```text
Tracing
Metrics
Audit / Events
```

## Distributed tracing

Every request receives:

```text
trace_id
```

Example:

```text
CLI request
  └─ router
      └─ orchestrator
          ├─ policy check
          ├─ retrieval
          ├─ model call
          ├─ tool call
          └─ artifact generation
```

## Agent trace

For each agent:

```text
START
 ↓
THOUGHT/PLAN SUMMARY
 ↓
TOOL CALL
 ↓
OBSERVATION
 ↓
STATE UPDATE
 ↓
TOOL CALL
 ↓
OUTPUT
```

Do not store hidden chain-of-thought as an observability requirement. Record concise action/decision summaries, tool inputs/outputs where permitted, provenance, and hashes.

```text
   ↓

  manual_17 v4 p27

   ↓

   ↓

```

## Immutable events

Use append-only event records and hash chaining.

Conceptually:

```text
event_n.hash =
SHA256(event_n.payload + event_(n-1).hash)
```

This creates tamper-evident history.
